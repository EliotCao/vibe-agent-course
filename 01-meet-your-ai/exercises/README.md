## 必做（3 题）

### 练习 1.1 · Token 估算挑战

**不用任何工具**估算下面三段文本的 token 数（接受 ±30% 误差）：

```
T1: "Hello, world! Welcome to vibe coding."
T2: "今天天气不错，我去公园散步了，路上看到很多小朋友在玩耍。"
T3: 你 01_llm.py 自己整个文件
```

提交：
- 你估的值
- 用 `count_tokens.py` 查到的实际值
- 反思：你估得偏高还是偏低？为什么？

### 练习 1.2 · 三人格对战

让 3 个不同 system prompt 的 AI **互相对话** 8 轮：

- A：你是热血少年漫主角，永远充满希望
- B：你是赛博朋克黑客，言简意赅
- C：你是温和的中学老师，喜欢提问

实现方式：
- 每轮按 A→B→C 顺序，每个人看到前面所有人说过的话
- 起手话题："我们今天聊聊'什么是好代码'吧"
- 跑 8 轮记录完整对话

提交：
- 完整对话日志
- 一段你的观察：对话有没有崩溃 / 变得重复 / 产生意外的好句子

> 这题考察你**多角色 messages 拼接**的能力，是 Day3 多 Agent 的预热。

### 练习 1.3 · 设计你自己的"防幻觉" system prompt

针对 Day1 第 4 节讲的 4 类幻觉触发器，写一份**强化的 system prompt**，要求：

- 包含至少 3 条防幻觉规则
- 包含至少 2 个 few-shot 示例（"用户问了 XX，你该怎么回"）
- 跑过 demo_04 的 4 个案例验证效果

跑同样的 4 个案例，对比"加强 system prompt 之前 vs 之后"。

提交：
- 你的 system prompt
- 4 个案例的"前/后"对比
- 反思：哪些场景改善明显？哪些还是会编？

## 选做（任选 1 题）

### 练习 1.4 · 朴素 RAG 小工具

写 `naive_rag.py`：

- 输入：一个文档（如 `README.md`）+ 一个问题
- 流程：把文档全文塞进 prompt → 让 LLM 基于文档回答
- 命令行：`python naive_rag.py README.md "什么是 VibeCoding"`

进阶（可选）：
- 文档太长时（> 4000 token），按段落切，**每段算一下与问题的关键词重合度**，挑前 3 段塞 prompt
- 这就是"朴素的检索"

提交：代码 + 至少 5 个真实问题的测试结果。

> 这是 Day4 上下文管理的预热。

## 答案要点（仅老师参考）

### 1.1
- T1 ≈ 11 token
- T2 ≈ 28-32 token
- T3 取决于学生代码长度，常见 600-1500 token
- 学生通常**低估**中文（1 字 ≈ 1 token 比想象的多）

### 1.2
- 对话超过 5 轮容易陷入"客气套话循环"
- 适当加 temperature 能保持新鲜感
- 这是 Day3 Reflection / 多 Agent 协作的伏笔

### 1.3
- 评分看 system prompt 里有没有具体规则（不是空话）
- few-shot 例子要能覆盖典型触发器
- 真实改进通常在"诚实表达不知道"上明显，"虚构 API"上仍易翻车

### 1.4
- "朴素检索"用关键词重合度即可（不需要向量）
- 这道题做完，学生对 RAG 的理解会比纯听理论深得多

### 1.5
- 主要看学生的对比维度是否丰富（不只是"哪个对哪个错"，要看代码风格、解释清晰度、token 性价比）
