【演示 ② · 用 old_content/new_content 替换 vs 用行号替换】
============================================================

为什么 edit 工具不接收 line_number 参数？

假设我们让 LLM 完成两步任务：
  Step 1: 在第 5 行前面插入一段新函数
  Step 2: 修改第 12 行的某个调用

如果 edit 接收行号：
  - Step 1 插入 3 行新代码后，原"第 12 行"现在变成第 15 行
  - LLM 不知道这点 → Step 2 改错了位置

但如果 edit 接收 old_content / new_content：
  - 不管前面增删多少行，"目标文本"还是那段
  - 永远精确

🎯 一句话：LLM 看到的世界是文本，不是行号。

============================================================
🎯 三个设计选择背后的共同思路
============================================================
  - 每个'安全约束'都是为了防止某种 LLM 翻车
  - LLM 不知道'行号会变'，所以工具自己用文本定位
  - LLM 不知道'rm -rf /' 多致命，所以工具自己拦
  - LLM 不知道'消息 50KB 太长'，所以工具自己截断

  工具的设计不是'实现功能'就完了，而是要'帮 LLM 不犯错'。
