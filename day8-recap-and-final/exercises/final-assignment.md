# 结课大作业

> **截止时间**：课程结束后 2 周
> **提交方式**：在 CNB 上的个人仓库，提交到 `final-project` 分支
> **可组队**：方向二允许 2-3 人自由组队

---

## 方向一：完善你的 Coding Agent（个人）

### 要求

在你 Day1-Day7 搭建的 Coding Agent 基础上，**至少添加 2 个特色功能**，让它在某个场景下明显比"裸版"更好用。

### 特色功能参考（不限于此）

| 功能 | 难度 | 说明 |
|------|------|------|
| 并行工具调用 | ★★ | 一次 LLM 回复里多个 tool_calls 并行执行，加速 |
| 流式输出 + 进度条 | ★ | 最终回答逐字输出，工具调用阶段显示 spinner |
| 代码索引（tree-sitter） | ★★★ | 解析项目所有文件的函数/类，让 Agent 定位更精准 |
| 多文件 diff 预览 | ★★ | edit 前先显示 diff，让用户确认再执行 |
| 会话持久化 | ★ | 退出 REPL 后再次启动能恢复上次对话 |
| 自动生成 commit message | ★ | 每次修改完代码自动 `git add + commit`，message 由 LLM 写 |
| Web UI | ★★ | 用 Gradio / Streamlit 替代 CLI，支持文件树 + 对话 |
| 自我改进循环 | ★★★ | Agent 跑完任务后自动 review 自己的工具调用记录，提出优化建议 |
| 多 Agent 协作 | ★★★ | Planner Agent + Coder Agent + Reviewer Agent 分工 |
| 沙箱隔离 | ★★ | bash 工具在独立 Docker 容器里执行，主进程只收结果 |

### 验收标准

1. **代码提交**：`final-project` 分支，README 里写清新增了什么功能
2. **对比演示**：同一个任务，裸版 vs 你的加强版，截图/录屏证明改进效果
3. **NPC 仍能工作**：新功能不能 break NPC 链路（push 后 @ 还能回复）
4. **文档**：新功能的使用说明 + 设计思路（不超过 1 页）

## 方向二：自由发挥（2-3 人组队）

### 要求

用课程学到的 Agent 核心能力（LLM 调用 + 工具 + 循环 + 记忆），**vibe 出一个完整的 AI 产品**。方向不限、题目不限，只要求：

1. 是一个**可以跑起来、有真实用户交互**的产品（不是 PPT）
2. 至少用到课程里的 **3 个核心能力**（Function Calling / Agent Loop / Memory / Skills / NPC 任意 3 个）
3. 有一个**真实使用场景**（哪怕很小——"帮我每天总结 GitHub 热点"也算）

### 方向参考（不限于此）

| 方向 | 示例 | 用到什么 |
|------|------|---------|
| 学习助手 | "帮我把这篇论文拆成 Q&A 闪卡" | LLM + 工具（read PDF / write JSON）+ Memory（记住学过什么） |
| 运维机器人 | "监控告警来了自动排查 + 回复" | NPC 触发 + bash 工具 + 分层 Context |
| 面试模拟器 | "出题 → 学生答 → AI 评分 + 追问" | Agent Loop + Reflection（评分后 review） |
| 代码审查 Bot | "PR 提交后自动 review + 打分" | NPC + grep/read + Skills（团队规范） |
| 日报生成器 | "读 git log + Issue，自动写日报" | bash + LLM + 定时触发 |
| 个人知识库 | "丢链接进去，自动提炼 + 按主题归档" | Memory + Skills + Web 抓取工具 |
| 翻译 Agent | "保持代码格式，只翻译注释和字符串" | read + edit + 自定义 Skill（翻译规范） |

### 验收标准

1. **可运行**：评审时现场演示，至少跑通 3 个真实场景
2. **代码提交**：仓库里有完整代码 + README + 使用说明
3. **用到 3 个核心能力**：在 README 里标注"这里用了 Function Calling""这里用了 Memory"
4. **团队分工说明**：如果组队，每人贡献什么写清楚
5. **2 分钟 Demo 视频**（可选加分）

---

## 评分标准（满分 30 分）

| 维度 | 方向一 | 方向二 | 分值 |
|------|--------|--------|------|
| **功能完整性** | 2 个特色功能都能跑通 | 产品 3 个场景都能跑通 | 10 分 |
| **代码质量** | 模块清晰 / 错误处理 / 接口设计 | 同左 | 8 分 |
| **创意与实用性** | 功能选择的合理性 | 场景真实性 + 创新度 | 7 分 |
| **文档与演示** | 对比截图 + 设计说明 | Demo 视频 + README | 5 分 |

### 加分项（最多 +5 分）

- NPC 在真实开源项目上跑通并被采纳（+3）
- 方向二做出了真正有用户在用的产品（+5）
- 方向一实现了 3 个以上特色功能（+2）
- 代码有单测覆盖 ≥ 60%（+2）
