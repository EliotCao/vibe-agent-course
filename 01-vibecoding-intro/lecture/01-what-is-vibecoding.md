# 第 01 节 · 什么是 VibeCoding

> 一句话：**你负责"想要什么"，AI 负责"怎么写"。**

## 一、从"敲代码"到"说需求"

传统写代码：你得记住语法、查 API、调试报错，每一行都要自己敲。

VibeCoding（氛围编程）：你用**自然语言**描述想要什么，AI 把代码写出来，你看效果、提意见、让它改——像跟一个不知疲倦的实习生结对编程。

```
传统：  想法  →  自己查文档  →  自己写每一行  →  自己调 bug  →  能跑
Vibe：  想法  →  跟 AI 说一句  →  AI 写  →  你看效果提意见  →  AI 改  →  能跑
```

> 这个词最早由 Andrej Karpathy 提出，核心是："giving in to the vibes" —— 你不再逐字纠结代码，而是描述意图、感受结果、快速迭代。

## 二、VibeCoding 不是"不用懂代码"

它降低的是**动手门槛**，不是**理解门槛**。你依然需要：

- 能**描述清楚**自己想要什么（需求表达能力）
- 能**判断**AI 给的东西对不对（审美与品味）
- 知道哪里**不对劲**，并能引导 AI 修正（调试直觉）

AI 是放大器：想法清晰的人，它帮你飞；想法混乱的人，它帮你更快地造出一团乱麻。

## 三、跟 AI 协作的基本节奏

```
1. 说清楚目标   "我想要一个命令行猜数字游戏，1-100，有次数限制"
2. 让它先跑通   先要最小可运行版本，别一上来要 100 个功能
3. 看效果       亲自运行，看哪里不满意
4. 给具体反馈   "猜错时提示太大还是太小""加一个排行榜"
5. 小步快跑     一次改一点，每次都保持能跑
```

### 提需求的几个小技巧

| 技巧 | 反例 | 正例 |
|------|------|------|
| 具体 | "做个游戏" | "做个终端贪吃蛇，方向键控制，吃到食物变长" |
| 给约束 | "随便写" | "只用 Python 标准库，不要第三方依赖" |
| 一次一件事 | "加排行榜、联网、音效、皮肤" | "先加本地排行榜，存到 json 文件" |
| 带上报错 | "报错了" | 把完整报错贴给 AI，让它定位 |
