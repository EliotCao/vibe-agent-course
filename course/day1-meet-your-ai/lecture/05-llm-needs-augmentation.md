## 阶段 A · 抛问题（3min）

老师投屏直接问 LLM：

```
现在是北京时间几点几分？
```

模型回答有两种：
- "我无法获取实时时间" ← 老实型
- "现在是 14:30" ← 编型

无论哪种，**它都没办法真正知道**。

> "我们 Day1 学了 LLM 怎么聊天，但它有些事**永远不可能自己知道**。怎么办？"

## 阶段 B · 讲原理（10min）

### LLM 的 4 类"天生不知道"

| 类型 | 例子 |
|------|------|
| **实时信息** | 现在几点 / 今天天气 / 某股价 |
| **私域知识** | 你公司的内部文档 / 你仓库的代码 |
| **训练截止后的事** | 2025 年新闻 / 最新论文 |
| **执行结果** | 跑这段代码会输出什么 / 这个 API 返回啥 |

这 4 类信息**模型本身永远拿不到**。但通过两种方式可以"喂给它"：

### 方式 1：把信息塞进 prompt（朴素 RAG）

```python
prompt = f"""
我有一份内部文档：
---
{read_file('internal_policy.md')}
---

请根据这份文档回答：报销流程是什么？
"""
```

把外部信息**手动塞进 user message**，模型就能基于它回答。

**这就是 RAG 的最朴素版本**：检索（你手动检索）+ 增强生成。

#### 优点
- 简单，立竿见影
- 任何 LLM 都支持

#### 缺点
- 你要**手动决定塞什么**——模型自己没法选
- 信息一多就会撑爆上下文

### 方式 2：让 LLM 自己调工具

更进一步：**让模型自己决定调哪个工具**。

```
用户: 现在几点？
   ↓
LLM 思考: 我不知道，但有 get_current_time 工具，调它
   ↓
LLM 输出: tool_call: get_current_time()
   ↓
程序执行: 14:30
   ↓
LLM 把结果写成自然语言: "现在是 14:30"
   ↓
返回用户
```

**这就是 Agent 的雏形**——模型主动伸手向外部世界要信息。

> 我们 Day2 会专门实现这套机制。今天只先体感"加工具能解决问题"。

### 关键认知：LLM 是大脑，工具是手脚

类比：

| 角色 | 类比 |
|------|------|
| LLM | 一个聪明但被关在房间里、没有手机的天才 |
| 工具 | 给他配一台电话（查天气）、一个文件柜（读文档）、一支笔（写代码） |
| Agent | 天才 + 一套工具 + 决策"该用哪个" |

> 整个 VibeCoding 课程剩下 7 天都在围绕"给 LLM 配什么工具、怎么管"。

### 一个重要观察

回顾 Day1 学的 5 件事：

```
1. LLM 是 next-token 概率机器  →  解释了它"怎么思考"
2. 三种角色 + messages 协议    →  解释了"怎么跟它说话"
3. token + 上下文窗口          →  解释了"成本与边界"
4. 幻觉                         →  解释了"它的弱点"
5. 工具与上下文                 →  解释了"怎么补强弱点" ← 通往 Agent
```

**Day1 完整地回答了"LLM 是什么"。Day2 开始造 Agent。**

## 阶段 C · 当堂 demo（7min）

让学生跑：

```bash
python demo_05_with_tool.py
```

这个 demo 做两个实验，每个都是**前后对比**：

### 实验 1：当前时间

- ① 直接问 LLM：要么承认不知道，要么编一个
- ② 先调 `get_current_time()`，把结果塞进 prompt → 立刻精准回答

### 实验 2：内部文档

- ① 直接问"课程结业作业截止时间"：模型不知道，瞎说或承认
- ② 把内部文档贴进 prompt → 模型立刻精准回答

学生跑完会**看到一个朴素但震撼的事实**：

> **LLM 不是不能解决这些问题，只是它需要"被喂"信息。**

### 抛思考题（demo 后 2min）

留下问题让学生带去 Day2：

> demo 里我们手动调 `get_current_time()` 然后塞进 prompt。  
> 但如果有 100 个工具呢？让 LLM 自己**选**要调哪个，然后**自动**塞进去——这就是 Day2 要做的。

## Day1 整体总结

| 节 | 关键认知 |
|----|---------|
| 1 | LLM 是 next-token 概率机器，智能从规模涌现 |
| 2 | 跟它说话用 messages 协议，3 种角色 |
| 3 | Token 是钱、是边界、是工程问题源头 |
| 4 | 幻觉不是 bug 是本性，要识别要缓解 |
| 5 | 加工具 / 加上下文 = 弥补 LLM 弱点的方法 |
