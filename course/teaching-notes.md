# 教师须知（Teaching Notes）

> 本文写给授课老师与助教。学生看 `syllabus.md` 与每日 README 即可。

## 一、贯穿全程的 4 个原则

### 1. Vibe 优先，不要直接讲代码
"VibeCoding"的精髓是**让学生先尝试用自然语言驱动 AI 把功能跑起来**，再回头解释原理。每个实操**先给目标和提示词，再给参考代码**，顺序不能反。

### 2. 每天必须有"能跑的产物"
大二学生注意力集中时间有限。每个 3.5 小时的课，**最后 30 分钟必须看到自己的代码跑起来**，否则挫败感会累积到第二天。

### 3. 故意留坑，让学生踩
- Day1 让学生第一次写 prompt 时**不告诉**他们 system prompt 的存在，等他们出问题再讲
- Day2 实现 ToolRegistry 时让他们先用最 naive 的 dict 注册，再讲 Schema 自动生成的好处
- Day3 让 ReAct 版本先靠正则解析，故意让模型温度高一点跑崩，再讲 Function Calling 的优势
- Day4 让他们先不限上下文长度，跑 30+ 轮看 token 爆炸，再讲为什么要 ContextManager

### 4. 已有代码是"备用伞"，不是教材
`ch01`-`ch04` 是参考实现。**不要把链接丢给学生让他们抄**。卡到不行才掏出来对照。

## 二、整体节奏

```
Day1 (认知)  → Day2 (动手)  → Day3 (范式)  → Day4 (工程化基础)
                                                 ↓
                                          Day5 (工具集)
                                                 ↓
                                          Day6 (整合大爆发)
                                                 ↓
Day7 (Skills + NPC 上线)  → Day8 (复盘 + 大作业)
```

- Day1-3 是**认知与基础**，节奏可以稍慢，每天 1-2 个新概念扎实掌握
- Day4-5 是**工程化基础**，难度上升，要预留更多答疑时间
- Day6 是**全课程最难的一天**——整合时各种边界问题会冒出来。**助教必须配齐**
- Day7 是**最有成就感**的一天——看到自己的 Agent 在 Issue 里回复时学生会很兴奋
- Day8 主要是**收束 + 仪式感**，时间宽松一点

## 三、每天的关键风险点

### Day 1（认识 AI）
- **风险**：环境配置卡 1 小时
- **预案**：开课前 15min 统一发测试 token，让学生跑通 ping 脚本
- **常见坑**：Windows 学生 `os.environ` / 流式 print 不刷新

### Day 2（Function Calling + 最小 Agent）
- **风险**：ToolRegistry 自动生成 Schema 时反射机制不熟
- **预案**：先用手写 Schema 跑通，再讲怎么自动生成
- **常见坑**：tool_call_id 配对错 / arguments 是 string 不是 dict

### Day 3（Agent 范式）
- **风险**：3 种范式一天讲 + 跑，时间紧
- **预案**：ReAct 是"必跑"，Plan-and-Solve 和 Reflection 提供半成品代码让学生改而不是从零写
- **常见坑**：Plan-and-Solve 的 Planner 模型选错（用大模型贵、小模型蠢，建议同一个）

### Day 4（上下文与记忆）
- **风险**：上下文管理是抽象概念，学生没遇到过爆炸不会有体感
- **预案**：上午先让 Day3 Agent 跑一个 30 轮的任务，让上下文真的撑爆，下午再讲解决方案
- **常见坑**：摘要 LLM 调用没限制 token / 向量检索引入新依赖装不上

### Day 5（Coding Agent 工具集）
- **风险**：9 个工具一天写不完，学生进度差异大
- **预案**：把 9 个工具分成"必做 6 个 + 选做 3 个"。`webfetch` 和 `todo` 可以放到课后
- **常见坑**：`edit_file` old_str 唯一性这个设计点，**必讲**——这是真实工程级 Coding Agent 的关键
- **Git 速通**：放在 Day5 中段（理论 25 分钟之后），只讲 5 个命令：`init / add / commit / push / branch + PR`，目的是让 push 当作业提交方式

### Day 6（整合）
- **风险**：整合时各模块接口对不上，学生抓狂
- **预案**：老师**当场带做**，每 15 分钟一个 checkpoint，所有人同步进度
- **常见坑**：
  - ContextManager 没接进去，token 还是炸
  - Memory 没持久化，每次启动都空
  - Agent 主循环逻辑跟单元测时不一样

### Day 7（Skills + NPC 上线）
- **风险**：NPC 上线链路长（镜像 → 注册表 → Pipeline → 事件 → 容器 → 回写），任一环错都不工作
- **预案**：**Skills 实操优先**完成，NPC 上线给"参考 Dockerfile + entrypoint 直接用"，学生不需要从零写
- **Docker 速通**（30min）只讲：`docker build / run / push` + 一份现成 Dockerfile 模板
- **CNB+NPC**（30min）只讲：`.cnb.yml` 怎么写 + `.cnb/settings.yml` 怎么写 + 怎么 @ 触发
- **常见坑**：
  - `--workmode` 漏了导致评论作者不是 NPC
  - `CNB_NPC_TRIGGER_CONTENT` 拼错
  - 容器里没装 git-cnb

### Day 8（总结 + 大作业）
- **风险**：节奏太松散学生走神
- **预案**：用"学生分享"占满中段，每人必须上台 3 分钟

## 四、答疑预案（高频问题）

| 学生问题 | 老师怎么答 |
|---------|----------|
| "为什么 LLM 有时听话有时不听？" | 概率模型，本质是采样。讲 temperature |
| "Function Calling 比 prompt 注入工具好在哪？" | 结构化、解析稳、模型微调过专门支持。但本质都是给模型看一段文本 |
| "ReAct / Plan-and-Solve / Reflection 我该用哪个？" | 看任务：动作-反馈型用 ReAct；目标明确多步用 Plan-and-Solve；高质量输出用 Reflection。可组合 |
| "为什么我的 Agent 老死循环？" | LLM 没记住自己刚做了什么 + 没收到工具结果 → 引出**上下文管理**与 `max_iter` |
| "Memory 跟 Context 区别是什么？" | Context 是"这次对话的工作内存"，Memory 是"跨对话的长期存档"。两者协作 |
| "我的 Agent 写的代码不符合我项目风格" | 引出 Day7 Skills |
| "NPC 跑起来回复内容很傻" | 检查 prompt + 上下文是否给够。NPC 跟 REPL 模式相比少了多轮调试机会 |

## 五、考核与评分建议

每天 Checkpoint 占 10 分（共 70 分；Day8 不打分）；结课大作业 30 分。

**Checkpoint 评分维度**（各 2 分）：
- 实操产物可运行
- 反思 100-200 字
- 反思里有具体卡点
- 反思里有学到的概念
- 主动答过别人 1 个问题

**结课大作业评分维度**（共 30 分）：
| 维度 | 分数 |
|------|------|
| NPC 触发链路完整跑通 | 6 |
| Agent 任务有真实价值 | 6 |
| 至少 1 次"失败 → 修复 → 成功"迭代 | 6 |
| 代码质量（命名 / 注释 / 测试） | 6 |
| 录屏 + 总结文档 | 6 |
